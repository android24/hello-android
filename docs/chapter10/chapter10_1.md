# 10.1 为什么要学习 Android Framework

第 9 章里，我们已经开始用性能和稳定性的眼光看 App：启动慢、卡顿、ANR、崩溃、内存压力，这些问题都不再只是“代码写得好不好”的问题。

当你继续往下追，会发现很多答案藏在应用层下面。

为什么 `Activity` 会被创建？

为什么主线程不能被阻塞？

为什么一个点击会从系统一路送到你的 Composable 或 View？

为什么 Service、ContentProvider、系统服务之间总在谈 Binder？

第 10 章开始，我们正式进入 Android Framework。

## 本章通关画面

完成第 10 章后，你应该能把一次 App 启动讲成这样：

```text
用户点击图标
  -> Launcher 请求系统启动页面
      -> ActivityTaskManagerService 协调任务栈
          -> Zygote fork 出应用进程
              -> ActivityThread.main() 建立主线程消息循环
                  -> 创建 Application
                      -> 创建 Activity
                          -> 页面进入可交互状态
```

你不需要一下子读懂整个 AOSP。第 10 章的目标更朴素，也更重要：

```text
知道系统大概分几层，知道源码从哪里进，知道一条调用链如何被追下去。
```

## 本章故事线

可以把第 10 章想象成一次“后台参观”。

前 9 章里，你像一名 App 工程师，负责页面、数据、架构、测试和体验。现在你拿到了一张后台通行证，第一次走进 Android 系统的控制室：这里有主线程调度、有系统服务、有进程创建、有跨进程通信，也有那些平时只在面试题里出现的名字。

但我们不会一上来就把门全打开。

本章只做一件事：把最关键的几扇门认清楚。

## 本节定位

本节是第 10 章入口。

我们先回答三个问题：

- 学 Framework 到底有什么用？
- 为什么不建议零基础直接啃源码？
- 应用层经验如何变成源码阅读线索？

## 学习目标

学完本节后，你应该能够：

- 理解 Framework 学习和资深 Android 能力之间的关系。
- 知道 Framework 不是背源码，而是理解系统协作方式。
- 从启动、卡顿、页面跳转、事件分发等问题反向找到源码入口。
- 明白第 10 章 demo 的观察价值。

## 第一部分：Framework 不是另一门孤立课程

很多人学习 Framework 时会有一种割裂感：

```text
我平时写的是 Activity、ViewModel、Compose。
源码里看到的是 ActivityThread、AMS、Binder、Looper。
它们好像不是同一个世界。
```

其实它们一直在同一个系统里。

你写的 `Activity.onCreate()`，是 Framework 调度出来的。

你调用的 `startActivity()`，最终要跨进程请求系统服务。

你看到的 ANR，往往和主线程消息分发、输入事件、Binder 调用有关。

你优化启动速度，背后绕不开进程创建、Application 初始化和首帧绘制。

Framework 学习的意义，就是让这些“平时看不见的系统协作”变得可解释。

## 第二部分：什么时候该学 Framework

如果你还不能独立写一个页面、处理状态、完成网络请求、看懂生命周期日志，那么直接读 Framework 很容易迷路。

更合适的顺序是：

```text
先会写 App
  -> 再写出可维护的 App
      -> 再优化体验和稳定性
          -> 最后追到系统底层理解原因
```

这也是本课程把 Framework 放到第 10 章之后的原因。

前面章节不是绕路，而是在给源码阅读准备问题。

## 第三部分：源码阅读要带着问题进去

不要这样读源码：

```text
今天我要读完 ActivityThread。
```

更推荐这样读：

```text
Activity.onCreate() 是谁调用的？
主线程的 Looper 是在哪里创建的？
Handler 消息为什么能回到主线程？
startActivity() 为什么需要系统服务参与？
```

带着问题进入源码，路线会清晰很多。

源码不是森林探险，而是一张城市管网图。你要先知道自己要找的是水管、电线还是地铁，再决定从哪个井盖下去。

## 第四部分：第 10 章 demo 怎么用

第 10 章配套示例工程是：

```text
examples/10-framework-source-walkthrough/
```

它不是一个系统源码阅读器，而是一个“Framework 观察实验室”。

你可以在里面：

- 观察 `Application` 和 `Activity` 生命周期日志。
- 查看当前进程、线程、主 Looper 信息。
- 点击按钮发送一次 `Handler` 消息。
- 对照页面里的启动链路，理解 App 从图标点击到页面展示的大致过程。
- 根据源码入口清单去 AOSP 中定位 `ActivityThread`、`Looper`、`Handler`、`ContextImpl` 和 Binder 相关类。

## 本节小挑战

### Framework 入场券

请把自己当成第一次进入 Android 后台控制室的工程师。你不用马上修机器，只需要先认出三块仪表盘。

请先不用打开源码，只回答下面三个问题：

- 你觉得 `Activity.onCreate()` 是你主动调用的吗？
- 如果主线程没有 `Looper`，`Handler.post {}` 会发生什么？
- 为什么应用进程需要和系统服务通信？

## 本节小结

Framework 学习不是为了炫耀源码行号，而是为了让应用开发经验变得更有解释力。第 10 章会从系统架构、源码阅读方法、启动链路、主线程模型和 Binder 初识开始，帮你迈过“源码很大，不知从哪看”的第一道门。
