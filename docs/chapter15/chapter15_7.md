# 15.7 渲染体验问题：白屏、闪烁、过度绘制、黑屏与掉帧

前面我们建立了渲染链路。

这一节把知识放回真实问题：

- 页面白屏。
- 画面闪烁。
- 列表掉帧。
- 自定义 View 不刷新。
- 视频黑屏。
- 过度绘制。

这些问题看起来分散，但放进一帧链路后，都可以分类排查。

## 本节剧情钩子

用户说：

```text
打开页面的时候闪了一下。
```

产品说：

```text
列表滚动没有竞品顺。
```

测试说：

```text
偶现黑屏，但按钮还能点。
```

如果只在业务代码里乱翻，很容易迷路。

你需要的是一张渲染问题地图。

## 本节定位

本节是第 15 章的问题诊断章节，负责把渲染链路转化成实际排查能力。

## 学习目标

学完本节后，你应该能够：

- 用渲染链路分类显示体验问题。
- 区分白屏、闪烁、黑屏、掉帧和过度绘制。
- 知道每类问题的第一排查入口。
- 能写一份渲染问题诊断报告。

## 第一部分：白屏

白屏通常发生在页面内容还没有准备好时。

常见原因：

- Activity 启动后首帧太慢。
- 主题背景和真实内容衔接不好。
- 主线程初始化任务过重。
- 数据加载阻塞 UI。
- 首屏布局过重。

排查入口：

```text
Activity 启动时间
  -> 首帧时间
      -> 主线程初始化
          -> 首屏布局和绘制
```

白屏不是单纯“背景颜色不好看”，它常常是启动链路和渲染链路共同的问题。

## 第二部分：闪烁

闪烁通常意味着画面在短时间内出现了不稳定状态。

常见原因：

- 先显示默认内容，再立刻切换真实内容。
- 图片加载占位和真实图片切换突兀。
- 窗口切换或 Dialog 关闭时层级变化明显。
- 重组 / 重绘导致短暂空状态。
- Surface 内容重建。

排查入口：

```text
画面是否经历空状态？
窗口或 Surface 是否重建？
数据状态是否多次快速切换？
```

闪烁问题要关注“中间态”。

## 第三部分：过度绘制

过度绘制指同一区域被重复绘制多次。

例如：

- 父容器有背景，子容器也有满屏背景。
- 多层卡片、遮罩、透明背景叠加。
- 不必要的嵌套布局。
- 列表 item 内部层级过深。

过度绘制不一定立刻造成卡顿，但它会增加渲染成本。

排查入口：

```text
布局层级
  -> 背景叠加
      -> 透明区域
          -> GPU overdraw 工具
```

## 第四部分：黑屏

黑屏比白屏更偏显示链路或 Surface 内容问题。

常见场景：

- 视频播放器黑屏但控制层还在。
- 相机预览黑屏。
- SurfaceView 生命周期处理不当。
- Buffer 没有及时提交。
- 窗口存在，但内容 Surface 没有有效帧。

排查入口：

```text
View 是否存在？
Surface 是否创建？
Buffer 是否提交？
播放器 / 相机是否绑定正确 Surface？
```

如果普通 UI 正常，而视频或相机黑屏，就要特别关注 Surface 路径。

## 第五部分：掉帧

掉帧通常来自帧预算超时。

常见原因：

- 主线程做耗时任务。
- 频繁 requestLayout。
- onDraw 过重。
- 列表滚动时图片解码。
- Compose 重组范围过大。
- 阴影、模糊、裁剪、透明叠加太多。

排查入口：

```text
主线程耗时
  -> layout / draw 成本
      -> RenderThread / GPU
          -> SurfaceFlinger 合成
```

不要只说“优化一下”，要找到慢在哪一段。

## 第六部分：自定义 View 不刷新

常见原因：

- 内部数据变了但没调用 `invalidate()`。
- 尺寸变了但没调用 `requestLayout()`。
- onDraw 没有使用最新数据。
- View 不可见或尺寸为 0。
- 被父容器裁剪。

排查入口：

```text
数据是否变化？
是否触发 invalidate / requestLayout？
View 尺寸是否正常？
onDraw 是否执行？
```

这类问题最适合用第 15 章的一帧模型排查。

## 第七部分：渲染问题诊断表

| 现象 | 先看哪里 | 可能原因 | 修复方向 |
| --- | --- | --- | --- |
| 首屏白屏 | 启动耗时、首帧时间 | 初始化过重、首屏布局复杂 | 延迟非必要任务，优化首屏布局 |
| 画面闪烁 | 状态切换和窗口变化 | 中间空状态、占位切换突兀 | 稳定 UI 状态，优化占位和过渡 |
| 列表掉帧 | 主线程、布局、图片 | item 复杂、图片解码、频繁布局 | 简化 item，异步加载，减少 requestLayout |
| 过度绘制 | 布局层级和背景 | 多层背景、透明叠加 | 删除无效背景，降低层级 |
| 视频黑屏 | Surface 与播放器状态 | Surface 未绑定或 Buffer 未提交 | 检查生命周期和 Surface 绑定 |
| 自定义 View 不刷新 | invalidate / requestLayout | 数据变了但未请求刷新 | 根据变化类型选择刷新方式 |

## 本节小挑战

### 渲染诊断题

请为下面问题写出诊断路径：

```text
问题：列表页面打开后白屏 800ms，随后内容出现；第一次快速滚动明显卡顿，第二次滚动变流畅。
```

要求写出：

- 可能涉及哪些链路。
- 第一批应该收集什么证据。
- 你会先优化哪一段。

## 本节实践任务

- 找一个页面，列出可能导致白屏和掉帧的点。
- 按诊断表给每个点归类。
- 写一份 10 行以内的分析。

### 进阶任务

- 选择一个真实卡顿页面。
- 用工具采集一次证据。
- 区分主线程、绘制、图片、合成哪个更可疑。

## 本节小结

渲染体验问题看起来分散，但都可以放进一帧链路里分析。白屏看首帧，闪烁看中间态，过度绘制看层级和背景，黑屏看 Surface 与 Buffer，掉帧看帧预算，自定义 View 不刷新看 invalidate 和 requestLayout。排查渲染问题的关键，是把用户的一句“卡了”翻译成可验证的链路证据。
