# 15.6 VSYNC、帧率、掉帧与 Jank

前面我们已经把一帧从 App 侧刷新推进到了 SurfaceFlinger 合成。

这一节回到用户体验：

```text
为什么有时页面能显示，但就是不顺？
```

答案会遇到 VSYNC、帧率、掉帧和 Jank。

## 本节剧情钩子

用户不会说：

```text
你的 traversal 超时了。
```

用户只会说：

```text
这个页面有点卡。
```

工程师要做的，就是把“有点卡”翻译成证据：

- 哪一帧慢了？
- 慢在主线程？
- 慢在渲染？
- 慢在 Buffer 提交？
- 还是慢在合成？

## 本节定位

本节讲清楚流畅度问题的基本判断方式，为后续性能优化和渲染实验做准备。

## 学习目标

学完本节后，你应该能够：

- 理解 VSYNC 和帧率的基本关系。
- 知道掉帧和 Jank 的直观含义。
- 能把主线程耗时、绘制耗时和合成耗时联系起来。
- 知道常见流畅度工具能提供什么证据。

## 第一部分：VSYNC 是显示节拍

屏幕刷新有节奏。

常见 60Hz 屏幕大约每 16.6ms 有一次刷新机会。

简化理解：

```text
每一帧都有一个时间窗口。
你在窗口内完成，用户看到流畅画面。
你错过窗口，用户可能看到卡顿。
```

高刷新率屏幕时间窗口更短。

例如 120Hz 大约是 8.3ms 一帧。

这意味着高刷新率不是“更容易”，而是对性能提出更高要求。

## 第二部分：掉帧不是崩溃，但会伤体验

掉帧通常不是功能错误。

页面仍然能用，按钮也能点。

但体验会变差：

- 滚动不跟手。
- 动画一顿一顿。
- 页面切换卡一下。
- 首帧慢。
- 点击反馈迟缓。

这类问题很容易被低估，因为它不像 crash 那样明显。

但资深工程师必须能处理它。

## 第三部分：Jank 是不稳定的帧体验

Jank 可以理解为画面节奏不稳定。

不是每一帧都慢，而是某些帧突然慢。

例如：

```text
第 1 帧：正常
第 2 帧：正常
第 3 帧：慢很多
第 4 帧：正常
```

用户看到的就是“卡了一下”。

常见原因：

- 某一帧触发大量布局。
- 列表滚动中加载图片。
- 主线程突然执行 IO。
- GC 发生在关键时刻。
- 绘制命令太复杂。
- GPU 或合成压力过高。

## 第四部分：一帧慢在哪里

分析掉帧要拆层：

```text
Input
  -> Animation
      -> Traversal
          -> Draw
              -> Sync / Upload
                  -> GPU
                      -> SurfaceFlinger
```

不要只盯着一个点。

如果主线程有长任务，先处理主线程。

如果主线程看起来没问题，就继续看渲染线程、GPU、图片、阴影、过度绘制和合成。

## 第五部分：常见工具

流畅度问题需要工具证据。

常见工具包括：

- Android Studio Profiler：观察 CPU、内存和线程。
- Layout Inspector：观察布局层级。
- `dumpsys gfxinfo`：查看帧耗时统计。
- Perfetto：分析系统级时间线。
- Compose Tracing：分析 Compose 重组和绘制。
- Profile GPU Rendering：快速观察帧柱状图。

工具不是目的。

目的只有一个：

```text
找到哪一段超过了这一帧的预算。
```

## 第六部分：体验评分思路

第 15 章的 demo 可以继续沿用前面章节的“体验评分”机制。

例如把一帧观察拆成：

- 是否触发刷新。
- 是否区分 layout / draw。
- 是否记录帧回调。
- 是否模拟主线程忙碌。
- 是否观察滚动掉帧。
- 是否写出一帧报告。

这样读者不是被动阅读，而是在完成一场流畅度侦查。

## 本节小挑战

### Jank 线索题

请为下面现象写出第一排查入口：

- 列表第一次滚动很卡，第二次顺很多。
- 点击按钮后动画第一帧卡顿。
- 页面打开白屏 1 秒。
- 滚动时图片逐个出现并伴随掉帧。
- 主线程看起来不忙，但 GPU 指标异常。

## 本节实践任务

### 基础任务

- 打开一个列表页面。
- 快速滚动并观察是否有卡顿。
- 写下你认为可能慢在哪里。

### 进阶任务

- 使用 Profiler 或 `dumpsys gfxinfo` 观察帧数据。
- 找一次明显慢帧。
- 尝试解释它可能慢在哪一段。

## 本节小结

流畅度问题的核心是帧预算。VSYNC 给出节拍，Choreographer 安排工作，App、RenderThread、GPU 和 SurfaceFlinger 都要在合适时间完成各自任务。掉帧和 Jank 不是玄学，而是一帧链路中的某段超时。真正的优化从证据开始。
