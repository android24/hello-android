# 12.4 进程创建、Zygote 与 ActivityThread 协作

如果目标 Activity 所在进程还不存在，系统不能直接调用它的生命周期。

它必须先创建应用进程。

## 本节剧情钩子

有时候系统收到页面启动申请后，发现演员还没到场。

于是系统要先通知后台：“准备一个新的应用进程。”等进程起来、主线程消息循环准备好，Activity 才能被真正创建。

这时，Zygote、ActivityThread 和系统服务就开始接力。

## 本节定位

本节理解 Activity 启动和应用进程创建的协作关系。

## 学习目标

学完本节后，你应该能够：

- 知道 Activity 启动可能触发进程创建。
- 理解 Zygote 在应用进程创建中的作用。
- 知道 ActivityThread 是应用进程侧调度入口。
- 能把进程创建和 Activity 生命周期联系起来。

## 第一部分：目标进程可能不存在

当你启动一个 Activity 时，系统会判断目标应用进程是否已经存在。

如果不存在，系统需要先创建进程。

简化链路：

```text
ATMS / AMS 判断目标进程不存在
  -> 请求创建应用进程
      -> Zygote fork
          -> ActivityThread.main()
              -> 进入主线程消息循环
```

## 第二部分：Zygote 像进程模板

第 10 章已经初识 Zygote。

这里再从 Activity 启动角度理解一次：

```text
Zygote 不是 Activity 调度者。
它负责 fork 出应用进程。
```

系统服务决定要不要创建进程，Zygote 负责具体 fork，应用进程起来后由 ActivityThread 继续接管应用侧调度。

## 第三部分：ActivityThread 接收调度

应用进程启动后，会进入 `ActivityThread.main()`。

它准备主 Looper，并等待系统调度消息。

当系统准备启动目标 Activity 时，会把调度消息送到应用进程，最终触发生命周期回调。

简化理解：

```text
系统服务侧记录要启动谁
  -> 应用进程侧 ActivityThread 执行创建和生命周期
```

## 第四部分：冷启动为什么更复杂

冷启动比热启动复杂，因为它多了进程创建和应用初始化。

它可能包括：

- Zygote fork。
- Application 创建。
- 依赖注入初始化。
- 首个 Activity 创建。
- 首帧绘制。

这也是第 9 章启动优化和第 12 章 Framework 启动链路相遇的地方。

## 第五部分：demo 中怎么观察

第 12 章 demo 会显示进程启动年龄和生命周期日志。

你可以：

- 强制停止 App 后重新启动。
- 观察 MainActivity 首次生命周期。
- 再从首页启动详情页，观察是否还需要新进程。

普通同 App 页面跳转不会创建新进程，但它能帮助你区分“页面创建”和“进程创建”。

## 本节小结

Activity 启动可能先触发应用进程创建。系统服务负责判断和调度，Zygote 负责 fork 进程，ActivityThread 在应用进程里接收生命周期调度。理解这条线，冷启动、页面跳转和生命周期就不再是孤立概念。
