# 12.7 启动体验问题：黑屏、白屏、重复页面与返回异常

学 Activity 启动，不只是为了读源码。

它还直接关系到真实用户体验：打开慢、白屏、重复页面、返回异常、通知跳转错乱，都是项目里常见问题。

## 本节剧情钩子

系统调度像舞台换场。

如果布景还没准备好，观众会看到黑屏或白屏；如果演员重复上场，页面就会堆叠；如果退场路线没设计好，返回键就会让人迷路。

这一节从用户体验倒推启动链路。

## 本节定位

本节把 Activity 启动机制和工程问题联系起来。

## 学习目标

学完本节后，你应该能够：

- 理解黑屏白屏和启动链路的关系。
- 知道重复页面常和启动模式、Flag 有关。
- 能用生命周期日志分析返回异常。
- 知道启动问题要从现象、链路和证据一起排查。

## 第一部分：黑屏白屏

启动白屏或黑屏常见原因包括：

- 冷启动耗时过长。
- 启动主题配置不合理。
- Application 初始化过重。
- 首屏数据或 UI 构建太慢。
- Activity 创建到首帧之间有阻塞。

第 9 章讲性能，第 12 章讲启动调度，两者在这里汇合。

## 第二部分：重复页面

重复页面常见于：

- 多次快速点击启动按钮。
- 通知、深链、普通入口使用不同 Flag。
- 没有正确理解 `singleTop`、`CLEAR_TOP`。
- 业务层手动维护页面状态和系统栈冲突。

解决前要先画出当前返回栈。

## 第三部分：返回异常

返回异常通常表现为：

- 按返回键回到不该出现的页面。
- 从通知进入后返回桌面，而不是回到 App 内上级页。
- 登录页、首页、详情页之间反复跳。
- 清栈 Flag 使用过猛。

这些问题背后往往是 Task 和 Intent Flag 设计不清。

## 第四部分：排查三件套

遇到启动体验问题，建议准备三类证据：

```text
操作路径
  -> 生命周期日志
      -> Intent / Flag / launchMode 信息
```

如果能加上启动耗时和前后台状态，排查会更稳。

## 第五部分：demo 中怎么练

第 12 章 demo 会提供：

- 生命周期轨迹。
- 启动观察分数。
- 不同启动按钮。
- 返回栈任务卡。

你可以用它模拟：

- 普通页面堆叠。
- singleTop 复用。
- CLEAR_TOP 回首页。
- 返回键路径变化。

## 本节实践任务

### 基础任务

- 连续启动两次详情页。
- 按返回键观察路径。
- 判断是否出现重复页面。

### 进阶任务

- 用 `CLEAR_TOP` 回首页。
- 观察日志中的 `onDestroy()`。
- 写一份“返回异常排查清单”。

## 本节小结

启动体验问题往往不是单点代码错误，而是启动链路、任务栈、初始化耗时和入口设计共同作用的结果。学会用日志和返回栈还原现场，才能真正解决黑屏、白屏、重复页面和返回异常。
