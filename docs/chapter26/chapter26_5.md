# 26.5 性能、稳定性、安全与存储的综合检查

毕业项目跑起来，只是第一步。

终章真正要训练的是：你能不能像负责线上工程一样，检查它是否可靠、可诊断、可发布。

这一节，我们把性能、稳定性、安全和存储放到同一张检查表里。

## 本节先记住三句话

```text
功能完成不代表工程完成，能被检查、被观测、被回归才算接近交付。
性能、稳定性、安全和存储不是四个孤岛，它们经常在同一次事故里同时出现。
资深工程师的检查不是凭感觉，而是用指标、证据和边界条件说话。
```

## 为什么要综合检查

真实项目里很少出现“纯性能问题”或“纯权限问题”。

更常见的是：

```text
离线下载时写文件过慢
  -> 主线程被阻塞
      -> 页面卡顿
          -> 用户重复点击
              -> 后台任务重复入队
                  -> 存储状态混乱
                      -> 日志里还打印了敏感路径
```

这一次问题同时涉及：

```text
性能
稳定性
后台任务
存储
安全
日志
治理
```

所以毕业项目的检查也必须是综合的。

## 性能检查

建议至少检查这些路径：

| 路径 | 检查点 |
| --- | --- |
| 冷启动 | Application 初始化、首页首帧、ContentProvider、磁盘 I/O |
| 首页列表 | 列表滑动、图片加载、重组次数、帧耗时 |
| 课程详情 | 点击到内容可见耗时、本地缓存命中、网络刷新耗时 |
| 离线任务 | 入队耗时、后台执行耗时、重试次数 |
| 治理页面 | 报告生成耗时、大列表渲染、筛选排序开销 |

不要只写：

```text
性能良好。
```

更好的记录方式是：

```text
首页冷启动首帧：860ms
课程详情点击到内容可见：180ms
列表快速滑动最大帧耗时：24ms
离线任务入队：32ms
治理报告生成：46ms
```

数字不一定一开始就来自真实采集，也可以由 Demo 模拟。

但报告必须有“指标意识”。

## 稳定性检查

毕业项目至少要模拟这些稳定性场景：

| 场景 | 观察目标 |
| --- | --- |
| 主线程阻塞 | 是否能提示风险，是否能定位阻塞来源 |
| 协程异常 | 是否被捕获，UI 是否展示错误状态 |
| 后台任务失败 | 是否有重试、失败原因和用户反馈 |
| 进程被回收 | 学习进度和页面状态是否能恢复 |
| release 混淆 | crash 堆栈是否能通过 mapping 还原 |

稳定性不是“永远不出错”。

稳定性是：

```text
错误发生时不扩大。
错误发生后能定位。
修复以后能证明。
```

## 安全检查

毕业项目虽然不是金融 App，也应该练习安全意识。

至少检查：

| 项目 | 检查问题 |
| --- | --- |
| 权限 | 是否只申请必要权限，拒绝后是否可降级 |
| 日志 | 是否打印 token、用户笔记、文件路径等敏感信息 |
| 存储 | 笔记和进度是否明文暴露到公共目录 |
| 组件 | Activity / Service / Receiver 是否误设 `exported=true` |
| PendingIntent | 是否明确 immutable / mutable |
| Web / 外链 | 是否校验 URL，是否可能被恶意跳转利用 |

安全检查的重点不是吓人。

而是让学习者知道：

```text
系统给了能力，也要求你守边界。
```

## 存储检查

毕业项目中的学习进度、收藏、笔记、离线任务都和存储相关。

建议检查：

| 数据 | 存储策略 |
| --- | --- |
| 学习进度 | DataStore 或 Room |
| 收藏列表 | Room / 本地 fake database |
| 笔记 | Room，必要时考虑备份策略 |
| 离线任务状态 | Room + WorkManager 状态 |
| 图片缓存 | App 私有缓存目录 |
| 导出报告 | 通过 SAF 或系统分享，而不是直接写公共路径 |

这部分要和第 22 章保持一致：

```text
能放 App 私有目录的，不随便放公共目录。
需要用户选择文件位置的，用 SAF 或系统分享。
需要媒体索引的，才进入 MediaStore。
```

## 综合检查表

毕业项目可以准备一张总表：

| 检查类别 | 必查项 | 通过标准 |
| --- | --- | --- |
| 性能 | 冷启动、点击响应、列表滑动、报告生成 | 核心路径无明显卡顿，关键指标有记录 |
| 稳定性 | 异常捕获、任务失败、进程恢复、混淆还原 | 失败可感知、可定位、可回归 |
| 安全 | 权限、日志、组件、敏感数据 | 不越权、不误暴露、不泄露敏感信息 |
| 存储 | 私有数据、缓存、导出、URI 权限 | 数据位置合理，授权边界清晰 |
| 治理 | 发布清单、风险等级、监控基线 | 能给出发版结论和后续动作 |

这张表可以直接进入 Demo 的治理工作台。

## 趣味任务：给项目做一次体检

请把自己当成毕业项目的“上线医生”，为它做一次体检。

你要给出四个结论：

```text
哪里跑得慢
哪里容易崩
哪里可能越权
哪里上线前必须补证据
```

体检结果不要只写“健康”或“不健康”。

要写：

```text
现象
证据
风险等级
修复建议
回归方式
```

这就是从学习者走向工程负责人的关键变化。

## 本节复盘

本节我们把毕业项目放进综合检查：

```text
性能关注核心路径是否顺畅。
稳定性关注错误是否可控、可诊断、可回归。
安全关注权限、日志、组件和敏感数据边界。
存储关注数据放在哪里、谁有权访问、如何导出。
```
