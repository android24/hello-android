# 13.6 Dialog、PopupWindow、Toast 与输入法窗口

前面几节主要围绕 Activity 主窗口展开。

但真实 App 里，屏幕上经常不只有一个主窗口：

- Dialog 会盖在页面上。
- PopupWindow 会贴着某个控件弹出。
- Toast 会短暂提示。
- 输入法会从底部出现。

这些都和窗口体系有关。

## 本节剧情钩子

你点击“删除”，弹出确认 Dialog。

你点击输入框，键盘弹起。

你点击菜单，PopupWindow 出现。

它们看起来只是一些 UI 小组件，但在系统眼里，它们很可能是不同类型的窗口，拥有不同的层级、Token、焦点和生命周期规则。

## 本节定位

本节把常见特殊 UI 放回窗口体系中理解。

## 学习目标

学完本节后，你应该能够：

- 区分普通 View、Dialog、PopupWindow、Toast 和输入法窗口。
- 知道 Dialog 依赖宿主 Activity 的有效窗口 Token。
- 理解输入法为什么会改变页面可见区域。
- 能从窗口角度解释一些遮挡和泄漏问题。

## 第一部分：Dialog 不是 Activity 里的普通 View

Dialog 看起来像盖在 Activity 上的一层 View。

但它通常会创建自己的窗口，并依附在宿主 Activity 上。

这意味着它有一些窗口规则：

- 宿主 Activity 必须有效。
- 显示和隐藏要跟随生命周期。
- 可能影响焦点。
- 会出现在 Activity 主窗口之上。

如果 Activity 已经 finish，仍然尝试 show Dialog，就可能出现窗口 Token 异常。

## 第二部分：PopupWindow 更像轻量浮层

PopupWindow 常用于菜单、气泡、下拉选择。

它通常依附某个锚点 View 展示。

需要关注：

- 锚点 View 是否还存在。
- 弹窗是否超出屏幕。
- 横竖屏或窗口尺寸变化后位置是否正确。
- 页面销毁时是否及时 dismiss。

它比 Dialog 更轻，但仍然要遵守窗口和宿主生命周期。

## 第三部分：Toast 的规则在变化

Toast 是提示类窗口。

它适合短提示，不适合承载复杂交互。

现代 Android 对后台 Toast、自定义 Toast、显示时机等都有更多限制。课程里不需要死记版本差异，但要记住：

```text
Toast 是系统管理的提示能力，不是任意可控的小窗口。
```

如果需要复杂提示或交互，通常应该使用 Snackbar、Dialog 或页面内状态。

## 第四部分：输入法是特殊窗口

输入法不是简单“把键盘 View 加到你的布局底部”。

它是系统输入法窗口，会和当前获得输入焦点的窗口协作。

常见问题包括：

- 输入法遮挡输入框。
- 页面 resize 或 pan 行为不符合预期。
- Compose / View 对 WindowInsets 处理不同。
- Dialog 中输入框弹键盘时布局异常。

理解输入法窗口后，你会知道这类问题不能只盯着 EditText，也要看窗口焦点、Insets 和布局适配。

## 第五部分：生命周期是窗口安全线

特殊窗口最容易出问题的地方，是生命周期。

常见风险：

- Activity 销毁后还 show Dialog。
- Fragment View 销毁后还显示 PopupWindow。
- 异步回调回来时页面已经不在前台。
- 输入法焦点没有正确清理。

处理原则：

```text
显示窗口前确认宿主有效，
宿主销毁时及时释放窗口。
```

## 本节小挑战

### 它是谁

请判断下面场景更可能对应哪类窗口：

- 删除确认弹层。
- 点击更多按钮出现的菜单。
- 底部弹出的软键盘。
- “保存成功”的短提示。
- 覆盖在其他 App 上的悬浮球。

## 本节实践任务

### 基础任务

- 在示例页面弹出一个 Dialog。
- 旋转屏幕或返回页面，观察 Dialog 是否还在。
- 思考它和 Activity 生命周期的关系。

### 进阶任务

- 给输入框页面打开软键盘。
- 观察内容区域是否被压缩或遮挡。
- 写下输入法窗口对页面布局的影响。

## 本节小结

Dialog、PopupWindow、Toast 和输入法都不是孤立的小 UI。它们和窗口类型、Token、焦点、Insets、生命周期紧密相关。理解特殊窗口，能帮助你定位遮挡、BadToken、窗口泄漏和输入法适配问题。
