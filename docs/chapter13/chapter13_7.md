# 13.7 窗口体验问题：白屏、遮挡、泄漏与 BadToken

学 WMS 和窗口体系，不只是为了看源码，更是为了定位真实问题。

这一节我们把常见窗口体验问题放在一起：

- 启动白屏 / 黑屏。
- Dialog 或输入法遮挡。
- Window 泄漏。
- `BadTokenException`。
- 过度绘制与首帧慢。

## 本节剧情钩子

用户不会说：“你的 ViewRootImpl 调度慢了。”

用户只会说：

```text
点开怎么白了一下？
弹窗怎么还在？
键盘挡住输入框了。
返回后怎么崩了？
```

Framework 学习的价值，就是把这些模糊抱怨翻译成可定位的问题。

## 本节定位

本节把窗口知识转化为排查思路。

## 学习目标

学完本节后，你应该能够：

- 用窗口链路解释白屏和首帧问题。
- 从生命周期角度理解窗口泄漏。
- 用 Token 解释 `BadTokenException`。
- 区分 View 遮挡、Window 遮挡和输入法遮挡。
- 建立窗口问题排查清单。

## 第一部分：白屏和黑屏

启动白屏 / 黑屏常发生在用户点击图标之后、首帧内容显示之前。

它可能和这些因素有关：

- 启动主题背景。
- Application 或 Activity onCreate 耗时。
- 首屏布局过重。
- 首帧数据等待。
- 绘制链路未及时完成。

从窗口角度看：

```text
窗口已经出现，但业务内容还没有及时完成首帧。
```

优化思路包括：

- 使用合适的启动主题。
- 减少主线程初始化。
- 首屏先展示骨架或本地缓存。
- 推迟非首屏任务。

## 第二部分：遮挡问题

遮挡问题要先分类。

```text
同一个页面内部遮挡：View 层级问题。
Dialog 盖住页面：Window 层级问题。
输入法挡住输入框：输入法窗口 + Insets 问题。
悬浮窗盖住 App：系统窗口权限和层级问题。
```

分类清楚后，排查方向才不会乱。

不要一上来就改 `zIndex`。如果问题来自 Window 层级，应用内部 View 的层级调整可能根本无效。

## 第三部分：窗口泄漏

窗口泄漏常见于：

```text
Activity 已经销毁，但它创建的窗口还没有被移除。
```

例如：

- Dialog 没有 dismiss。
- PopupWindow 没有关闭。
- 异步回调回来后继续 show 弹窗。
- 页面 finish 后仍尝试更新窗口。

排查时要问：

- 这个窗口是谁创建的？
- 它依附哪个 Activity 或 Fragment？
- 宿主销毁时有没有释放？
- 异步回调是否检查了生命周期？

## 第四部分：BadTokenException

`WindowManager.BadTokenException` 很常见，也很有代表性。

它通常意味着：

```text
你想添加一个窗口，但系统认为它没有合法 Token 或宿主已经无效。
```

典型场景：

- Activity 已 finish 后 show Dialog。
- 使用了错误的 Context 创建窗口。
- 后台场景尝试显示需要前台窗口的 UI。
- Fragment 脱离 Activity 后仍显示弹窗。

它不是“弹窗坏了”，而是窗口身份证不合法。

## 第五部分：过度绘制与首帧慢

窗口显示后，绘制内容也可能过重。

常见问题：

- 背景层层叠加。
- 首屏 Compose / View 层级过深。
- 图片过大。
- 列表首屏 item 创建过多。
- 同步等待网络数据。

这类问题和第 9 章性能治理相连。窗口链路让你知道“首帧在哪里”，性能工具让你知道“时间花在哪里”。

## 第六部分：窗口问题排查清单

遇到窗口问题，可以按这个顺序问：

```text
1. 这是 View 内部问题，还是 Window 层级问题？
2. 宿主 Activity / Fragment 是否仍然有效？
3. 是否涉及 Dialog、PopupWindow、输入法或悬浮窗？
4. 是否有正确的窗口 Token？
5. 是否和首帧、主线程耗时、布局过重有关？
6. 是否能用日志、Layout Inspector、Profile 工具找到证据？
```

## 本节小挑战

### 问题归类题

请归类下面问题：

- 点击按钮后弹窗偶发崩溃。
- 输入框在键盘弹起后被遮住。
- 首次打开页面白屏 1 秒。
- 页面里一个卡片盖住了按钮。
- Activity 退出后日志提示 window leaked。

## 本节实践任务

### 基础任务

- 找一个真实或模拟的 Dialog 弹出场景。
- 写出它的宿主是谁。
- 思考宿主销毁时应该在哪里 dismiss。

### 进阶任务

- 选择一个白屏或首帧慢场景。
- 写出从点击启动到首帧显示可能经过的链路。
- 标记你认为最可能耗时的节点。

## 本节小结

窗口问题看起来分散：白屏、遮挡、泄漏、BadToken、输入法、过度绘制。放进窗口体系后，它们都能找到位置。先判断问题属于 View、Window、Token、Insets、生命周期还是绘制性能，再选择工具和代码入口，这就是 Framework 学习带来的排查能力。
