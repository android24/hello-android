# 22.7 存储体验问题：文件丢失、媒体不可见、URI 失效与数据迁移

前面几节讲的是存储机制。

这一节开始进入真实事故。

存储问题很少以“我不懂 Scoped Storage”的形式出现。

它通常这样出现：

```text
用户说导出的文件找不到。
测试说保存到相册后相册不显示。
运营说换手机后离线课程全没了。
客服说用户选过的文件下次打不开。
线上说 Android 13 后图片上传失败。
产品说清缓存后用户草稿丢了。
```

这类问题最麻烦的地方是：它们看起来像功能 bug，根上却是数据归属、权限、索引、迁移或生命周期设计错了。

## 本节定位

本节负责回答：

- 存储事故应该如何建立证据链？
- 文件丢失、媒体不可见、URI 失效分别该查什么？
- 数据迁移为什么不是复制文件那么简单？
- 导入导出、清缓存、备份恢复如何避免体验事故？
- 如何把一次存储问题写成可复盘报告？

## 学习目标

学完本节后，你应该能够：

- 用“现象 -> 数据归属 -> 存储入口 -> 权限状态 -> 系统索引 -> 修复方案”的方式排查问题。
- 区分文件真的丢了、索引不可见、权限失效和路径假设错误。
- 能设计存储迁移和回滚策略。
- 能为清缓存、导入导出和备份恢复设计回归用例。
- 建立存储事故复盘模板。

## 第一部分：存储事故五步排查法

遇到存储问题，不要先猜路径。

先按五步走：

```text
第一步：确认数据归属
  -> App 私有、用户媒体、用户文档、缓存、跨应用共享？

第二步：确认存储入口
  -> filesDir、cacheDir、MediaStore、SAF、ContentProvider？

第三步：确认权限与授权
  -> runtime permission、Uri permission、持久授权、部分授权？

第四步：确认系统索引
  -> MediaStore 是否有记录？IS_PENDING 是否结束？MIME_TYPE 是否正确？

第五步：确认生命周期
  -> 卸载、清缓存、迁移、备份恢复、账号切换是否会影响？
```

这套顺序很重要。

如果你一上来只看：

```text
File.exists()
```

很可能会误判。

因为问题可能不是文件不存在，而是：

```text
相册索引不到
Uri 权限没了
用户只授权了部分照片
文件在 App 私有目录但用户找不到
旧路径在新版本不可访问
file:// 分享被系统拦截
分享文件未脱敏
```

## 第一部分补充：把事故拆成五类

存储事故可以先粗分成五类，这样不容易乱：

| 类型 | 表面现象 | 第一证据 | 常见根因 |
| --- | --- | --- | --- |
| 写入类 | 提示成功但文件不完整 | 输出流、文件大小、异常日志 | 半成品未回滚、主线程中断、空间不足 |
| 可见性类 | 文件存在但用户看不到 | MediaStore 记录、IS_PENDING、MIME_TYPE | 没进系统索引、写错集合、pending 未结束 |
| 授权类 | 以前能读，现在不能读 | Uri permission、AppOps、异常类型 | 没持久授权、用户撤销、部分授权 |
| 生命周期类 | 升级、清理、恢复后丢失 | 清理日志、迁移状态、备份配置 | 数据分级错、迁移不完整、索引和文件不一致 |
| 分享类 | 其他 App 打不开或不该看到 | content Uri、MIME_TYPE、grant flag | file:// 暴露、临时授权缺失、分享范围过大 |

这张表可以帮助你决定第一步看哪里：

```text
不要把授权问题查成文件丢失
不要把索引问题查成保存失败
不要把清理策略问题查成系统兼容
不要把迁移问题查成用户误删
不要把分享授权问题查成目标 App bug
```

## 第二部分：事故一：导出的文件找不到

现象：

```text
用户点击“导出学习报告”。
页面提示成功。
用户打开文件管理器找不到。
卸载 App 后文件也没了。
```

第一判断：

```text
这份报告属于用户，还是属于 App？
```

如果报告是用户要拿走、分享、归档的文件，它就应该有用户可理解的位置。

常见根因：

```text
导出文件写到了 filesDir
没有提供分享或保存入口
文件名不可读
没有告诉用户保存位置
卸载 App 后私有文件被清理
```

修复方向：

```text
使用 ACTION_CREATE_DOCUMENT 让用户选择保存位置
或写入 MediaStore Downloads
导出成功后展示文件名和保存位置
提供分享入口
```

回归用例：

```text
导出后用系统文件管理器查找
分享到其他 App
卸载 App 后确认用户导出文件仍保留
重复导出同名文件
导出失败时不留下半成品
```

## 第三部分：事故二：保存图片后相册看不到

现象：

```text
App 保存海报成功。
文件大小正常。
系统相册没有显示。
```

第一判断：

```text
它是不是被系统当作媒体登记了？
```

排查清单：

```text
是否通过 MediaStore 插入？
DISPLAY_NAME 是否有正确扩展名？
MIME_TYPE 是否是 image/png 或 image/jpeg？
RELATIVE_PATH 是否在 Pictures 等合理目录？
IS_PENDING 是否已更新为 0？
输出流是否正确关闭？
写入失败后是否误报成功？
```

修复方向：

```text
统一通过 MediaStore 保存用户媒体
写入时使用 IS_PENDING
成功后清 pending
失败时删除半成品 Uri
```

不要靠“扫描路径”作为主要方案。

现代 Android 里，系统索引比路径更重要。

## 第四部分：事故三：用户选过的文件下次打不开

现象：

```text
用户第一次选择课程包，可以导入。
下次打开 App，继续访问这个 Uri 报权限错误。
```

第一判断：

```text
这是一次性授权，还是长期授权？
```

常见根因：

```text
没有请求持久授权 flag
没有调用 takePersistableUriPermission()
只保存了 Uri 字符串，没有保存授权状态
用户撤销了权限
Provider 内容变化或文件被移动
```

修复方向：

```text
长期访问时持久化 Uri 权限
只需导入时，复制到 App 私有目录后释放依赖
下次访问前校验权限
失败时引导用户重新选择
```

这里有个关键选择：

```text
长期读外部文件
  -> 持久 URI 授权

导入后由 App 管理
  -> 复制到 App 私有目录
```

不要把一次性选择误当成永久拥有。

## 第五部分：事故四：清缓存清掉了用户草稿

现象：

```text
用户点击清缓存。
空间确实释放了。
但未发布草稿也没了。
```

第一判断：

```text
草稿是不是被错误归类成缓存？
```

常见根因：

```text
草稿附件放在 cacheDir
清理逻辑按目录粗暴删除
没有数据分级
没有清理白名单和黑名单
没有清理前预估影响
```

修复方向：

```text
草稿移到 filesDir 或数据库索引管理目录
缓存目录只放可再生数据
清理前展示分类和大小
清理后记录操作日志
为草稿增加恢复和同步策略
```

清缓存要记住：

```text
用户可以接受重新加载图片。
用户不能接受自己的内容凭空消失。
```

## 第六部分：事故五：升级后旧文件读不到

现象：

```text
旧版本把文件放在 /sdcard/AppName/。
升级 targetSdk 后，新版本读不到旧文件。
用户说历史资料丢了。
```

第一判断：

```text
这是数据丢失，还是迁移路径失效？
```

存储迁移要考虑：

```text
旧路径是否还能访问？
是否需要用户授权迁移？
迁移目标是 App 私有目录、MediaStore 还是 SAF 目录？
迁移是否可中断和恢复？
迁移失败是否保留旧数据？
是否有迁移版本号？
```

推荐迁移流程：

```text
启动时检测旧数据
  -> 评估是否有访问权限
      -> 提示用户迁移或选择旧目录
          -> 分批复制到新存储位置
              -> 校验数量、大小、hash
                  -> 写入迁移状态
                      -> 成功后再清理旧索引
```

不要在启动首屏静默迁移大量文件。

这可能带来：

```text
启动慢
ANR
电量消耗
半迁移状态
用户不理解空间变化
```

迁移还要设计“可观测性”。

至少记录：

```text
migration_version
source_location
target_location
total_count
success_count
failed_count
skipped_count
current_item
last_error
started_at
finished_at
```

这样当用户说“资料丢了”时，你可以区分：

```text
没有触发迁移
迁移中断
迁移失败
迁移成功但索引没更新
迁移成功但 UI 查询条件错了
```

没有迁移日志的迁移，就像没有黑匣子的飞行：出了事只能猜。

## 第七部分：存储事故报告模板

建议每次存储事故按下面模板复盘：

```text
问题标题：
用户现象：
Android 版本：
targetSdk：
设备 / 厂商：
数据类型：
数据归属：
存储入口：
文件或 Uri：
是否 App 私有：
是否共享媒体：
是否 SAF 授权：
是否持久 Uri 权限：
是否媒体权限：
是否部分照片授权：
是否 MediaStore 索引：
MIME_TYPE：
RELATIVE_PATH：
IS_PENDING：
是否参与备份：
是否被清缓存：
是否经历迁移：
第一证据：
根因判断：
修复方案：
回归用例：
监控指标：
```

这份报告要回答的不是：

```text
哪行代码报错？
```

而是：

```text
这份数据为什么在这个授权、索引和生命周期下表现成这样？
```

## 第八部分：本节自测

请回答：

- 文件存在但相册不可见，第一怀疑点是什么？
- Uri 字符串保存下来了，为什么下次仍可能没权限？
- 清缓存为什么要先做数据分级？
- 存储迁移为什么要支持中断恢复？
- 导出文件找不到，为什么可能是数据归属判断错了？
- 存储事故报告里为什么要记录 targetSdk 和 Android 版本？

## 本节小结

存储问题排查不能只盯路径。

```text
路径
权限
URI 授权
媒体索引
数据归属
清理策略
迁移状态
备份恢复
```

这些因素一起决定了用户看到的结果。

第 22.7 节的关键结论是：

```text
存储事故不是文件事故，而是数据身份、授权边界和生命周期事故。
```
