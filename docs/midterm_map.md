# 课程中期地图：从会写 App 到读懂系统

如果你已经走到第 20 章，说明这门课已经完成了第一段长坡。

你不再只是“把页面写出来”，而是已经经历了 Android 工程成长中最重要的几次转身：

```text
从语法到页面
  -> 从页面到数据
      -> 从数据到架构
          -> 从架构到工程质量
              -> 从工程质量到性能稳定性
                  -> 从应用代码到 Android Framework
```

这份中期地图不是新的知识点，而是一张回望和前行的路线图。它帮助你确认：前 20 章到底学到了什么，它们之间如何连接，后面为什么要继续进入后台调度、存储、安全、观测工具和大型工程治理。

## 第一阶段：把 App 跑起来

对应章节：

```text
第1章 Kotlin 与 Android 基础
第2章 Compose UI 基础
第3章 Activity、生命周期与导航
```

这一阶段解决的是最朴素的问题：

```text
我如何创建一个 Android 工程？
我如何写出一个页面？
我如何让页面响应点击、保存状态、跳转和返回？
```

你会从 Kotlin、Android 工程结构、资源文件、Compose UI、Activity 生命周期和 Intent 跳转开始，建立最基本的 App 直觉。

这一阶段学完后，你应该能说清楚：

- 一个 Android 工程大概由哪些文件组成。
- Compose 页面为什么会随着状态变化而刷新。
- Activity 是如何创建、暂停、恢复和销毁的。
- 页面之间如何通过 Intent 或导航参数传递信息。

这一阶段的关键词是：

```text
能运行
能看见
能点击
能跳转
```

## 第二阶段：让 App 拥有真实业务能力

对应章节：

```text
第4章 网络、Room 与 DataStore
第5章 Android 应用架构演进
第6章 Kotlin Coroutines、Flow 与后台任务
```

这一阶段开始把 App 从“页面演示”推向“真实业务”。

页面不应该只展示写死的数据，它需要网络、本地缓存、配置存储、异步加载、错误处理、刷新、取消、重试和后台任务。

更重要的是，代码不能一直堆在一个地方。你开始接触 MVC、MVP、MVVM、MVI / UDF、Repository、UseCase 和 Clean Architecture，理解为什么工程需要边界。

这一阶段学完后，你应该能说清楚：

- 网络、本地数据库和配置存储各自适合解决什么问题。
- Repository 为什么不只是“再包一层”。
- ViewModel 承载的不是页面控件，而是 UI 状态。
- 协程相比 Thread 和线程池，便利性和结构化优势在哪里。
- Flow 为什么适合表达“会随时间变化的数据”。
- WorkManager 为什么适合可靠后台任务，而不是普通线程的替代品。

这一阶段的关键词是：

```text
数据链路
架构边界
异步控制
状态流动
```

## 第三阶段：让工程可协作、可交付

对应章节：

```text
第7章 Hilt 依赖注入、模块化与工程化
第8章 测试、质量保障与可交付
第9章 Android 性能优化与稳定性治理
```

这一阶段开始回答工程现场最现实的问题：

```text
多人协作时，代码如何不互相踩踏？
需求变化时，工程如何不越来越乱？
上线前，如何知道这个版本值得交付？
出了性能和稳定性问题，如何定位和治理？
```

你会学习依赖注入、模块化、构建变体、测试替身、单元测试、Compose UI 测试、CI、静态检查、启动优化、卡顿分析、内存治理、ANR 治理、Crash 治理和包体积优化。

这一阶段学完后，你应该能说清楚：

- Butter Knife 为什么会退出主流工程，Hilt 为什么更适合现代依赖装配。
- 模块化不是把文件夹拆开，而是把边界、依赖方向和协作方式拆清楚。
- 测试不是为了追求覆盖率数字，而是为了保护核心业务规则。
- 性能优化不是凭感觉改代码，而是围绕启动、帧率、内存、线程和证据展开。
- 稳定性治理不是“遇到 Crash 修 Crash”，而是要有日志、分级、复盘和回归。

这一阶段的关键词是：

```text
工程边界
质量门禁
性能证据
稳定性闭环
```

## 第四阶段：进入 Android Framework

对应章节：

```text
第10章 Android Framework 入门、系统架构与源码阅读方法
第11章 Binder、SystemServer 与系统服务入门
第12章 AMS / ATMS、Activity 启动与任务栈调度
第13章 WMS、Window、DecorView 与窗口显示机制
第14章 Input 事件分发、触摸系统与交互响应机制
第15章 View 绘制、RenderThread、SurfaceFlinger 与渲染链路
第16章 PMS、应用安装、包管理与权限机制
第17章 资源系统、AssetManager、Resources 与主题机制
第18章 ClassLoader、Dex、Dalvik / ART 与动态加载机制
第19章 Android 进程模型、Zygote、应用沙箱与内存管理机制
第20章 ANR、Crash、Watchdog 与系统稳定性诊断机制
```

这一阶段不再只问“这段业务代码怎么写”，而是继续往下问：

```text
一次启动为什么能启动？
一次点击为什么能到达 View？
一个窗口为什么能显示？
一帧画面为什么能上屏？
一个资源 ID 为什么能找到字符串和图片？
一个类为什么能被加载？
一个进程为什么会出生、运行、被杀死？
一个 ANR 或 Crash 为什么能被系统发现和记录？
```

Framework 阶段最重要的收获，不是背类名，而是建立系统链路感。

你应该逐渐能把这些点串起来：

```text
Launcher 点击图标
  -> Binder 请求系统服务
      -> AMS / ATMS 调度 Activity
          -> Zygote fork App 进程
              -> ActivityThread 进入应用主线程
                  -> Window / DecorView / ViewRootImpl 接入窗口
                      -> InputDispatcher 分发事件
                          -> Choreographer 调度一帧
                              -> RenderThread / SurfaceFlinger 渲染合成
                                  -> Resources / ClassLoader / ART 支撑资源与代码运行
                                      -> ANR / Crash / Watchdog 记录异常现场
```

这一阶段学完后，你应该能说清楚：

- Framework 不是遥远源码，而是每一次页面启动、点击、绘制和崩溃背后的运行路径。
- Binder 是 App 与 system_server 协作的核心通道。
- AMS / ATMS 管的是 Activity 启动、任务栈和进程调度。
- WMS、Window、ViewRootImpl 决定页面如何接入屏幕。
- Input、View 绘制、RenderThread 和 SurfaceFlinger 共同决定交互和渲染体验。
- PMS、Resources、ClassLoader、ART、Zygote 分别支撑安装、资源、代码加载和进程运行。
- ANR、Crash、tombstone、DropBox、bugreport 是系统留给工程师的事故证据。

这一阶段的关键词是：

```text
系统链路
源码入口
跨进程协作
运行时机制
事故证据
```

## 你现在应该具备的能力

走完前 20 章，你不一定已经是资深工程师，但你应该已经具备了通往资深工程师的骨架。

你应该能做到：

- 能从零搭一个 Android App，并完成页面、数据、异步和导航。
- 能用架构分层解释一个功能应该放在哪里。
- 能判断一段异步代码是否有取消、超时、错误和生命周期风险。
- 能为核心业务写基础测试和交付检查。
- 能用性能和稳定性视角审视一个功能是否可上线。
- 能从一次启动、点击、绘制、安装、资源加载、类加载、进程创建中找到 Framework 入口。
- 能面对 ANR、Crash、Native Crash 和系统级问题时，先找证据，再写结论。

更重要的是，你应该开始拥有一种工程直觉：

```text
不要只问“代码怎么写”
还要问“它运行在哪里”
不要只问“功能能不能跑”
还要问“它出了问题时我能不能查”
```

## 继续往后：为什么还需要第 21 章以后

第 20 章之后，课程不会继续随意堆知识点，而是进入资深工程师更常遇到的复杂系统场景。

建议后续路线：

```text
第21章 后台任务、前台服务、Alarm、JobScheduler 与系统后台限制
第22章 存储系统、Scoped Storage、MediaStore 与数据访问机制
第23章 Android 安全模型、权限、签名、AppOps 与数据保护
第24章 系统观测工具：Perfetto、dumpsys、bugreport 与证据链分析
第25章 大型 Android 工程治理：模块边界、构建效率、发布、监控与团队协作
第26章 终局综合项目：从业务 App 到可诊断、可维护、可演进的 Android 工程
```

这些章节会把前 20 章学到的机制继续落到真实工程里。

第 21 章会回答：

```text
为什么后台任务会丢？
为什么保活方案经常不可靠？
为什么前台服务越来越受限制？
WorkManager、JobScheduler、AlarmManager 和 Service 的边界在哪里？
```

第 22 章会回答：

```text
文件、图片、视频、下载、导入导出和备份恢复，为什么越来越不能随便访问？
Scoped Storage、MediaStore、SAF 和 ContentProvider 各自解决什么问题？
```

第 23 章会回答：

```text
权限、签名、沙箱、导出组件、深链、WebView 和数据保护，如何影响一个 App 的安全底线？
```

第 24 章会回答：

```text
出了复杂问题，如何用 Perfetto、dumpsys、bugreport、logcat、gfxinfo 和 simpleperf 拿到证据？
```

第 25、26 章会把这些能力收束成大型工程判断：

```text
如何设计模块边界？
如何提升构建效率？
如何做发布、灰度、监控和复盘？
如何把一个课程 App 打磨成可诊断、可维护、可演进的完整工程？
```

## 三条学习路径

如果你是初学者：

```text
第1章 -> 第2章 -> 第3章 -> 第4章 -> 第5章 -> 第6章
```

先把 App 写出来，把页面、数据、状态和异步弄清楚。

如果你已经能做业务开发：

```text
第5章 -> 第6章 -> 第7章 -> 第8章 -> 第9章
```

重点补架构、协作、质量、性能和稳定性。

如果你想冲击中高级或资深：

```text
第9章 -> 第10章 -> 第11章 -> ... -> 第20章 -> 第21章以后
```

重点建立证据意识、系统链路意识和工程治理意识。

## 中期通关问题

读完这份地图后，可以用下面这些问题检查自己：

- 我能不能从零解释一个 App 是如何启动到首屏展示的？
- 我能不能解释一次点击如何从系统输入走到 View 或 Compose 处理？
- 我能不能解释一次页面卡死应该先看 logcat、trace 还是代码？
- 我能不能区分 Java Crash、Native Crash、ANR 和后台进程死亡？
- 我能不能说清楚资源、类、Dex、进程、线程和 Binder 在运行时分别承担什么角色？
- 我能不能把一个问题写成“现象、证据、根因、修复、回归”的诊断报告？

如果这些问题里有一半以上已经能回答出来，那么你已经不再只是 Android 入门者。

你正在进入真正有意思的地方：不只是写 App，而是理解 App 为什么能够运行，以及它为什么会在某些时刻失效。
