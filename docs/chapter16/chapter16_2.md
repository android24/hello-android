# 16.2 APK 安装流程：从文件到已安装应用

上一节我们建立了 PMS 的整体定位。

这一节从最常见的问题开始：

```text
一个 APK 是如何从文件变成系统里的已安装应用的？
```

安装不是复制文件这么简单。它包括解析、校验、写入、更新包信息、处理权限和通知系统。

## 本节剧情钩子

你把一个 APK 拖进手机。

安装界面显示：

```text
正在安装...
```

几秒后，它变成一个桌面图标。

看起来很简单。

但系统内部要确认很多事：

- 文件能不能读。
- 包名是否合法。
- 版本能不能升级。
- 签名是否匹配。
- Manifest 是否能解析。
- 安装路径在哪里。
- 哪些用户可以使用。
- 权限状态如何初始化。

这就是安装流程的真实复杂度。

## 本节定位

本节讲清楚 APK 安装主线，为后续 Manifest 解析、签名校验、权限和安装失败分析打基础。

## 学习目标

学完本节后，你应该能够：

- 理解 APK 安装不是简单复制文件。
- 知道 PMS 在安装流程中的核心职责。
- 初步理解扫描、解析、校验、提交和广播通知。
- 能解释常见安装失败为什么可能来自多个阶段。

## 第一部分：安装流程的简化主线

可以先把安装理解成这条链：

```text
提交 APK
  -> 读取安装参数
      -> 解析 APK 与 Manifest
          -> 校验包名、版本、签名、权限
              -> 拷贝或确认安装文件
                  -> 更新 PMS 内存数据和持久化数据
                      -> 发送包变化通知
                          -> Launcher / Settings 等刷新状态
```

真实源码里会更复杂，但这条主线足够帮你定位问题。

## 第二部分：安装入口不只有一个

APK 安装可能来自：

- adb install。
- 系统安装器。
- 应用商店。
- 企业设备管理。
- 系统开机扫描预装 App。
- OTA 后重新扫描。

不同入口参数可能不同，但最终都要进入包管理体系。

这也是为什么你在排查安装问题时，要先确认：

```text
这个包是通过什么路径安装或扫描进来的？
```

## 第三部分：解析阶段

解析阶段会读取 APK 中的重要信息。

核心是：

```text
AndroidManifest.xml
```

系统会解析：

- package。
- versionCode / versionName。
- minSdk / targetSdk。
- application。
- activity / service / receiver / provider。
- uses-permission。
- intent-filter。
- queries。

如果 Manifest 有问题，安装流程可能很早就失败。

## 第四部分：校验阶段

校验阶段会确认这个 APK 是否允许安装。

常见校验包括：

- 包名是否合法。
- 是否和已有包冲突。
- 版本是否允许升级或降级。
- 签名是否和旧版本一致。
- SDK 版本是否满足。
- 安装位置是否可用。
- 是否违反系统策略。

很多安装失败都发生在这里。

例如：

```text
INSTALL_FAILED_UPDATE_INCOMPATIBLE
INSTALL_FAILED_VERSION_DOWNGRADE
INSTALL_FAILED_NO_MATCHING_ABIS
INSTALL_FAILED_INVALID_APK
```

这些错误不是随机报错，而是安装链路中的某个规则拒绝了它。

## 第五部分：提交阶段

安装通过校验后，系统会提交结果。

包括：

- 确认 APK 路径。
- 更新包信息。
- 写入持久化配置。
- 处理权限初始状态。
- 更新组件可用状态。
- 发送 package added / changed 广播。

这一步之后，其他系统组件才能看到新的应用状态。

## 第六部分：安装和多用户

Android 支持多用户。

一个包在设备上存在，不代表每个用户都安装或启用。

简化理解：

```text
包文件可以是全局的，
安装状态可以是按用户区分的。
```

这解释了为什么有些包管理 API 会带 userId 或 UserHandle。

PMS 不是只维护“设备上有哪些 APK”，还要维护“哪个用户能使用哪些包”。

## 本节小挑战

### 安装失败分类题

请判断下面失败可能发生在哪个阶段：

- APK 文件损坏。
- 新版本签名和旧版本不一致。
- versionCode 比已安装版本低。
- ABI 不匹配。
- 安装后桌面图标没有刷新。

## 本节实践任务

### 基础任务

- 使用 `adb install` 安装一个 debug APK。
- 记录安装成功或失败信息。
- 思考失败信息对应安装流程哪一段。

### 进阶任务

- 尝试安装同包名不同签名的 APK。
- 观察系统报错。
- 写下签名校验为什么能阻止覆盖安装。

## 本节小结

APK 安装不是复制文件，而是一次完整的系统准入流程。PMS 会解析 Manifest、校验版本和签名、确认安装位置、更新包信息、处理用户安装状态，并通知系统其他部分。理解安装主线后，安装失败就能从“报错字符串”变成“流程中的具体拒绝点”。
