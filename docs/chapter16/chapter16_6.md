# 16.6 应用升级、卸载、数据保留与多用户状态

应用不是只安装一次就结束。

真实设备里还有：

- 升级。
- 卸载。
- 清除数据。
- 禁用组件。
- 多用户安装状态。
- 系统预装 App 更新。

这一节看 PMS 如何维护应用生命周期里的包状态。

## 本节剧情钩子

你卸载了一个 App，再安装回来。

有时数据还在，有时数据没了。

你升级了一个 App。

有时成功，有时签名或版本拦住。

你禁用了一个组件。

代码没变，但它突然无法被查询或启动。

这些都说明：包管理不只关心“APK 文件在不在”，还关心状态。

## 本节定位

本节讲清楚应用安装之后的状态变化，为排查升级失败、卸载残留、组件禁用和多用户问题打基础。

## 学习目标

学完本节后，你应该能够：

- 理解升级和首次安装的差异。
- 知道卸载和清除数据不是一回事。
- 理解 disabled component 和用户状态对组件查询的影响。
- 初步理解多用户下包状态为什么更复杂。

## 第一部分：升级不是重新安装

升级时，系统要确认：

- 包名一致。
- 签名一致。
- versionCode 合法。
- 兼容旧数据。
- 权限变化如何处理。
- 组件变化如何更新。

如果这些校验通过，系统会替换 APK 并更新包信息。

用户数据通常会保留。

这也是为什么升级失败常常和签名、版本、Manifest 变化有关。

## 第二部分：卸载和清除数据

卸载通常意味着移除应用安装状态。

清除数据通常意味着保留应用，但删除用户数据。

简化理解：

```text
卸载：应用不再可用。
清除数据：应用还在，但回到初始状态。
```

不同设备策略、系统 App、保留数据选项和多用户状态会让行为更复杂。

排查时要明确用户做的是：

- uninstall。
- clear data。
- disable。
- uninstall for user。

## 第三部分：系统预装 App 和更新

系统预装 App 可能位于 system、product、vendor 等分区。

用户安装的更新包可能位于 data 分区。

这会带来一种现象：

```text
卸载更新后，App 回到系统预装版本。
```

这不是“卸载失败”，而是系统 App 的包状态机制。

## 第四部分：组件 enabled 状态

组件可以被启用或禁用。

例如：

```kotlin
packageManager.setComponentEnabledSetting(...)
```

组件禁用后，可能表现为：

- Launcher 图标消失。
- Intent 查询不到。
- Service 无法启动。
- Receiver 不再接收广播。

所以组件不存在和组件被禁用，要分开判断。

## 第五部分：多用户状态

Android 多用户下，包信息会更复杂。

可能出现：

```text
包在设备上存在，
但当前用户未安装或已禁用。
```

这会影响：

- Launcher 展示。
- PackageManager 查询。
- Activity 启动。
- 权限状态。
- 数据目录。

Framework 源码里经常出现 userId，不是多余参数，而是包状态的一部分。

## 第六部分：状态问题诊断表

| 现象 | 可能原因 | 第一排查方向 |
| --- | --- | --- |
| 升级失败 | 签名不一致、versionCode 降级 | 查看签名和版本 |
| 卸载后图标仍像存在 | 系统预装 App 或多用户状态 | 区分卸载更新和彻底卸载 |
| 组件突然找不到 | enabled=false 或 Manifest 变化 | 查询组件 enabled 状态 |
| 某用户看不到 App | 多用户安装状态不同 | 检查 userId 和 user state |
| 清除数据后权限变化 | 用户授权状态被重置 | 检查 runtime permission |

## 本节小挑战

### 包状态推理题

请判断下面现象更可能是什么状态变化：

- 系统 App 卸载后重启又出现。
- Activity 代码存在，但 Launcher 图标消失。
- 同一设备主用户能打开 App，工作资料用户看不到。
- 升级后数据还在。
- 清除数据后登录状态消失但 App 还在。

## 本节实践任务

### 基础任务

- 安装一个 debug App。
- 升级同签名高 versionCode 版本。
- 观察数据是否保留。

### 进阶任务

- 禁用一个组件。
- 使用 PackageManager 查询它是否还能被解析。
- 写下“组件不存在”和“组件禁用”的差异。

## 本节小结

包管理不仅记录 APK 文件，还维护安装、升级、卸载、数据、组件启用和用户状态。升级不是重新安装，卸载不等于清除数据，系统预装 App 和多用户会让状态更复杂。理解这些状态，才能解释安装后看不到、组件突然消失、卸载不彻底和升级失败等问题。
