# Hello Android Capstone 终章回顾玩法手册

这份手册用于指导第 26 章精品 Demo 的学习过程。

它的目标不是让你把页面点完，而是让你通过动手把前 25 章重新复盘一遍。

## 推荐顺序

```text
课程回顾地图
  -> 毕业挑战模式
      -> 分阶段毕业路线
          -> 终章任务板
              -> 动手回顾实验室
                  -> 课程主路径
                      -> Framework 因果链
                          -> 事故剧本
                              -> 证据时间线
                                  -> 能力雷达
                                      -> 发布门禁
                                          -> 操作记录
                                              -> 毕业答辩报告
```

## 先确认工程现场

开始体验前，先看页面里的“工程快照与真实观察点”。

请确认这些信息：

```text
applicationId 是不是你当前运行的包
versionName / versionCode 是不是你当前验证的版本
BUILD_PROFILE 是 debug-capstone 还是 release candidate
debug 是否符合预期
sessionStartMs 是否代表本次会话
```

然后打开 Logcat，过滤：

```text
HelloCapstone
```

当你点击“重新追踪一次点击链路”或“注入当前事故证据”时，应该能看到对应日志。这个动作很小，但它训练的是一种重要习惯：先确认现场，再解释问题。

## 每一步要留下什么证据

| 步骤 | 你要做什么 | 要留下的证据 |
| --- | --- | --- |
| 工程快照 | 确认 AppId、版本、构建配置、会话时间 | 当前运行对象没有看错 |
| 毕业挑战模式 | 按 6 个关卡推进终章 | 哪些关卡已通过，哪些还缺证据 |
| 课程回顾地图 | 选择一个阶段，回答关键问题 | 一句话说明这个阶段训练的能力 |
| 终章任务板 | 把任务状态切到合适位置 | 哪些任务完成，哪些仍然需要补证据 |
| 动手回顾实验室 | 完成一个跨章节任务 | 操作记录、章节映射、验收说明 |
| 课程主路径 | 选择章节并追踪 traceId | 点击到 UI 刷新的事件序列、Logcat 记录和 Trace section |
| Framework 因果链 | 解释关键节点 | 因果句式，而不是类名堆叠 |
| 事故剧本 | 注入一次事故证据 | 现象、时间线、根因、自动推进的任务状态和修复方向 |
| 能力雷达 | 找到短板 | 至少一个下一步改进计划 |
| 发布门禁 | 判断能不能发 | P0 / P1 / P2 / P3 与发布结论 |
| 操作记录 | 回看最近关键动作 | 操作时间、动作名称、影响范围 |
| 答辩 Rubric | 对照 60 / 70 / 80 / 90 / 95 分标准 | 自己当前能证明到哪一层 |
| 毕业报告 | 复制或分享报告 | 一份包含工程快照、短板、门禁、Rubric 和答辩建议的材料 |

## 因果句式

讲 Framework 时，推荐这样表达：

```text
因为用户点击了课程卡片
  -> 所以系统要把输入事件送到正确窗口
      -> 所以 InputDispatcher 需要判断目标窗口
          -> 所以 ViewRootImpl 把事件交给 App 侧 UI 树
              -> 所以 Compose clickable 才能触发业务 intent
                  -> 所以 ViewModel 和 Repository 开始加载课程详情
                      -> 所以 Choreographer 安排下一帧显示新状态
```

这比只说“InputDispatcher 调 ViewRootImpl”更接近资深工程师的表达方式。

## 最小毕业标准

```text
主路径能跑通
至少 6 个任务状态为已完成
至少 1 个任务明确标记为需要补证据
至少完成 2 个事故剧本诊断，其中一个来自资源、权限、签名或类加载方向
至少能讲 1 条 Framework 因果链
至少能解释 mapping 和签名两个 P0 为什么阻塞发布
最终报告能被复制或分享
```

如果这些都做到了，第 26 章 Demo 就不再只是一个页面，而是一份可以展示的毕业作品。

## 动态能力雷达怎么玩

能力雷达会跟随你的操作变化：

```text
任务从未开始变成已完成
  -> 对应能力分提高

任务停在需要补证据
  -> 分数不会直接归零，但会提醒你还缺证明材料

P0 门禁未通过
  -> 工程治理和表达答辩会受到影响

P0 门禁修复
  -> 毕业结论会从暂缓毕业继续向答辩预演推进
```

这套机制想传达一个简单但重要的判断：

```text
工程能力不是“我做了”，而是“我做了，并且能证明”。
```

## 毕业挑战模式怎么玩

挑战模式把终章拆成 6 步：

```text
1. 选定回顾路线
2. 跑一次真实点击链路
3. 注入一次事故
4. 补一条动手证据
5. 修复 P0 门禁
6. 生成答辩材料
```

它的价值不是增加仪式感，而是把读者从“随便看看”拉回“逐步通关”。

每完成一步，页面会更新挑战进度。最后生成报告时，报告也会带上挑战完成度和每一步的证据说明。

## 操作记录怎么看

操作记录会保留最近 12 次关键动作。

它可以回答三个问题：

```text
你刚才做了什么？
这个动作影响了哪个章节、剧本、任务或门禁？
这一步能不能作为验收证据写进报告？
```

如果操作记录里只有“打开页面”，说明读者还没有进入真正的终章训练；如果记录里出现了追踪链路、注入事故、推进实验、修复门禁，说明他已经开始把课程能力重新串起来。

## 事故注入怎么玩

事故剧本不是普通选项卡。它会影响工程状态。

推进规则很直接：

```text
未开始 -> 进行中
进行中 -> 需要补证据
需要补证据 -> 继续保持，需要你补材料
已完成 -> 保持已完成，不因为注入事故倒退
```

```text
注入详情卡顿
  -> 事故诊断任务被推进
  -> Framework 因果链任务被推进
  -> 证据时间线替换为主线程与帧耗时线索

注入资源错乱
  -> 资源实验任务被推进
  -> 时间线出现 AAPT、resources.arsc、Theme、Configuration 线索

注入签名异常
  -> 安全检查与发版治理任务被推进
  -> P0 门禁仍然要求你补齐签名证据
```

请注意这里的设计：Demo 不会因为你点了一下事故按钮就替你毕业。它只是把“事故发生后哪些任务必须被重新关注”暴露出来。

## 真实观察点

本 Demo 已经接入这些真实工程信号：

```kotlin
Trace.beginSection("CapstoneRunTrace")
Trace.beginSection("CapstoneIncident:<scenarioId>")
Log.i("HelloCapstone", "runTrace ...")
Log.w("HelloCapstone", "simulateIncident ...")
SystemClock.elapsedRealtime()
BuildConfig.BUILD_PROFILE
```

推荐观察方式：

```text
1. 先打开 Logcat，过滤 HelloCapstone。
2. 点击“重新追踪一次点击链路”。
3. 确认日志里的 traceId、chapterId 与页面一致。
4. 注入一个事故剧本。
5. 确认日志、页面证据时间线、任务状态三者互相吻合。
6. 有条件时打开 Android Studio Profiler 或 Perfetto，观察 Trace section。
```

如果页面说发生了事故，但日志、Trace、任务状态没有任何对应变化，那就说明 Demo 还停留在“讲故事”。精品 Demo 必须让故事和证据互相咬合。

## 答辩 Rubric

终章答辩可以按这张梯度自检：

| 分数 | 你能证明什么 |
| --- | --- |
| 60 分 | 主路径能运行，读者能看见完整页面流转 |
| 70 分 | 架构边界能解释，依赖方向不是靠口头保证 |
| 80 分 | Framework 因果链能讲清，知道现象背后的系统节点 |
| 90 分 | 事故诊断和发布门禁形成闭环，P0 / P1 能影响发布结论 |
| 95 分以上 | 能提出真实工程演进，包括 CI、Perfetto、Baseline Profile、DataStore 或监控平台 |

答辩时可以这样问自己：

```text
别人问“为什么这样设计”，我有没有架构证据？
别人问“为什么是这个根因”，我有没有时间线证据？
别人问“为什么不能发布”，我有没有门禁证据？
别人问“下一步怎么做”，我有没有优先级和取舍？
```

能经得起这些追问，终章项目就开始有作品感了。
